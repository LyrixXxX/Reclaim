# Reclaim purchase verification

This Cloudflare Worker verifies the non-consumable `remove_ads` product against Google Play's ProductPurchaseV2 API and acknowledges a verified, unacknowledged purchase with `purchases.products.acknowledge`. It stores no purchase tokens. If server acknowledgment fails, the response identifies that condition so the Android app can attempt Google Play Billing acknowledgment and retry later. It is configured to deploy to the **existing** `reclaim-play-purchases` Worker at `https://reclaim-play-purchases.reclaim-nutrition.workers.dev`. Do not deploy it under a new Worker name.

`GOOGLE_SERVICE_ACCOUNT_JSON` is a **Cloudflare Worker secret**, never an Android `EXPO_PUBLIC_` variable or a repository file. Before deployment, add the complete JSON credential for `reclaim-purchase-verifier@reclaim-play-integrity.iam.gserviceaccount.com` to that existing Worker's **Settings → Variables and Secrets** as a Secret with the exact name `GOOGLE_SERVICE_ACCOUNT_JSON`. The Wrangler config requires the secret and refuses deployment without it. Avoid pasting the JSON into chat or putting it in a shell command. Cloudflare dashboard secret changes create a deployment; do this only when ready to update the Worker.

The Wrangler config adds two approximate, per-Cloudflare-location limits: 30 verification requests per minute per connecting IP and 300 total per minute. Confirm namespace IDs `2001` and `2002` are unused by other Workers in this account before deployment. A missing binding, limiter failure, or missing credential returns a non-entitling error. The endpoint also bounds request bodies to 8 KiB. These controls limit abuse but do not provide a strict worldwide quota; monitor Cloudflare and Google API usage.

Workers Logs is enabled for fixed operational failure codes only. Automatic invocation logs are disabled and query strings are redacted so request URLs cannot expose tokens in observability. Never log request bodies, purchase tokens, service-account JSON, OAuth tokens, Google response bodies, or raw exceptions. Preview URLs are disabled; the existing workers.dev URL remains enabled. The `2026-09-19` compatibility date is intentional: this Worker uses standard Fetch, Web Crypto, streams, and rate-limit bindings available at that date, and does not require a later compatibility flag. Review and test before changing the date.

Verification diagnostics distinguish `purchase_verifier_invalid_secret`, `purchase_verifier_oauth_signing_error`, `purchase_verifier_oauth_transport_error`, `purchase_verifier_oauth_http_error`, `purchase_verifier_oauth_response_error`, `purchase_verifier_play_lookup_transport_error`, `purchase_verifier_play_lookup_http_error`, and `purchase_verifier_play_lookup_response_error`. HTTP errors include only a numeric status. These codes do not change the response or grant entitlement. After deploying a diagnostic change, tap **Restore purchase** once and inspect the new warning in the purchase Worker's Observability view; do not make another test purchase merely to diagnose a failing lookup. Never share a full request or Google response body.

From the repository root, after authenticating Wrangler to the same Cloudflare account and adding the secret, deploy the reviewed code to the existing Worker with:

```powershell
npm exec --yes --package=wrangler@latest -- wrangler deploy --config services/play-purchases/wrangler.jsonc
```

Do **not** run that command until ready to replace the Worker's code. For the next internal Play test AAB, set `EXPO_PUBLIC_RECLAIM_PURCHASE_VERIFIER_URL=https://reclaim-play-purchases.reclaim-nutrition.workers.dev` in the release-build PowerShell session. The URL is public; the service-account JSON stays only in Cloudflare. Then test a Play license-tester purchase, pending purchase, restore, and refund/revoke. The app retries Google Play acknowledgment for verified purchases after launch, foregrounding, or Restore if an earlier acknowledgment was interrupted.

The app keeps ads disabled if this service is unreachable or its response is not valid. After deploying this acknowledgment change, use a new license-tester purchase and confirm the order stays processed beyond the short test acknowledgment window, including after app restart and Restore purchase. Do not enable live monetization until the public privacy policy, AdMob IDs, and end-to-end purchase/restore/refund tests pass.
