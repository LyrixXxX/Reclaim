# Reclaim privacy and monetization launch checklist

This checkout keeps ads and billing **off** unless all required release values are explicitly set. The default Android AdMob app ID is Google's test ID, so a normal local build remains non-monetized.

For a local, non-revenue banner test, set `EXPO_PUBLIC_RECLAIM_TEST_ADS_ENABLED=1` and `EXPO_PUBLIC_RECLAIM_MONETIZATION_ENABLED=0` before running `scripts/build-local-android.ps1`. This mode forces Google's sample Android app ID and adaptive banner unit, shows the banner on Home only after consent permits ads, and leaves purchases disabled. It requires no personal AdMob IDs or purchase verifier. Do not ship this test-only build to production or enable both flags together.

1. Create a separate Reclaim support inbox. Finalize `docs/privacy/index.html`: replace every bracketed item, remove the draft banner and `noindex`, check each statement against the release build, and obtain appropriate legal review. Publish that HTML from a separate public policy-only site (for example, GitHub Pages); do not publish this app repository or any credentials. Put the HTTPS URL in Google Play's privacy policy field.
2. Complete the Google Play Health apps, Data safety, Advertising ID, and ads declarations from the final Android binary. The ad SDK is included even when Reclaim's own ad switch is off, so do not assume an inactive placement means no SDK data handling or no ads declaration. Review Google Mobile Ads' current SDK disclosures and confirm the policy covers them.
3. Create an AdMob app and one anchored adaptive Home banner unit. Configure Google's consent/privacy messaging, including applicable US-state choices. The app requests only non-personalized ads and never passes user records as keywords or ad extras. Do not use production ads on test devices; use AdMob test-device registration during Play internal testing.
4. In Play Console, create an active **non-consumable** `remove_ads` product at **$4.99 USD** for the US launch. The in-app UI displays Google's localized product price; it does not hard-code `$4.99`.
5. Deploy `services/play-purchases/worker.mjs` as a Cloudflare Worker. Set `GOOGLE_SERVICE_ACCOUNT_JSON` as a Worker secret. Give that service account only the Play Console permission needed to read purchases, and add rate limiting to the public endpoint. Do not put its JSON key or a Google OAuth token in app config. Test purchased, pending, refunded, malformed, and provider-error responses.
6. In the release-build PowerShell session, set these build-time variables to real values: `EXPO_PUBLIC_RECLAIM_MONETIZATION_ENABLED=1`, `EXPO_PUBLIC_RECLAIM_PRIVACY_URL`, `EXPO_PUBLIC_RECLAIM_SUPPORT_EMAIL`, `EXPO_PUBLIC_ADMOB_APP_ID`, `EXPO_PUBLIC_ADMOB_BANNER_ID`, and `EXPO_PUBLIC_RECLAIM_PURCHASE_VERIFIER_URL`. The build script rejects missing/test ad IDs and non-HTTPS policy/verifier URLs. These AdMob IDs and URLs are public identifiers, not secrets. The Stadia Maps key remains required separately.
7. Install the resulting Android build from a Google Play internal-testing track and test first purchase, pending/cancelled purchase, restore, reinstall, second phone on the same Play account, and refund. Confirm an unknown purchase state or verifier outage produces **no ad**, and that no ad appears on onboarding, the app lock, health screens, forms, or active routes. A streamed APK does not substitute for Play Billing testing.

Do not switch the monetization flag on until every preceding item is complete. Core Reclaim features remain available when ad loading, billing, or the verifier fails.
